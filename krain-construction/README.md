# Krain Construction LLC — website

A complete, production-ready marketing site for **Krain Construction LLC** (Murrysville, PA),
built by **Forward Framework**.

Static HTML/CSS/JS generated by a small Python script. No framework, no build toolchain,
no runtime dependencies — every page is a plain file that any host will serve instantly.

```bash
python3 build.py            # generate ./site
python3 build.py --serve    # generate, then preview at http://localhost:8080
```

## Conversion architecture

Everything on the page exists to produce one of two actions: a phone call or a form submission.

- **Three-step quote form** on every page (hero, every service page, every city page, contact,
  FAQ). Step one is a single tap on a project type, which auto-advances — short first steps are
  the single biggest lever on completion rate. Progress bar, inline validation, honeypot.
- **Dedicated thank-you landing page** (`/thank-you/`) that greets the visitor by first name,
  echoes the project type they selected, sets a four-step expectation timeline, and keeps a
  call-to-action live. `noindex`, with hooks for GA4 / Google Ads conversion events.
- **Click-to-call everywhere** — top bar, sticky header, hero, every CTA band, and a fixed
  two-button action bar pinned to the bottom of every mobile screen.
- **Proof above the fold** — years in business, star rating, review count, Real Log Homes®
  authorization, licensed/insured, all visible before a scroll.
- **Trust ladder down the page** — services → differentiators → process → gallery → reviews →
  FAQ → CTA. The visitor's objections are answered in the order they occur to them.

## SEO

- Unique title (≤62 chars) and meta description (110–160 chars) per page — the build **prints a
  warning** if a future edit pushes either outside SERP limits.
- Canonical URLs, Open Graph + Twitter cards, generated 1200×630 share image.
- Semantic HTML, exactly one `h1` per page, no heading-level jumps, breadcrumbs on every page.
- Full internal linking mesh: services ↔ cities ↔ related services.
- `sitemap.xml` with per-page priority and change frequency; `robots.txt`.
- **Zero render-blocking third-party requests.** Fonts load async with `font-display: swap`;
  all imagery is inline SVG, so the site renders even before a single external byte arrives.

## AEO (answer engines)

- **JSON-LD `@graph`** on every page: `GeneralContractor` / `HomeAndConstructionBusiness` /
  `LocalBusiness`, `WebSite`, `WebPage`, `BreadcrumbList`, plus `Service`, `FAQPage`, `Review`,
  `AggregateRating`, `Place`, `OfferCatalog`, `OpeningHoursSpecification`, `GeoCircle` and
  `Person` where relevant.
- **"Quick answer" blocks** at the top of every substantial page — a single self-contained
  paragraph written to be lifted verbatim into an AI answer.
- **56 question-and-answer pairs** across the site, every one marked up as `FAQPage`.
- `speakable` markup on answer blocks, `h1` and FAQ answers.
- Comparison and fact tables (general contractor vs. single trade, company facts) — the
  structured format answer engines extract most reliably.

## GEO (generative engines)

- **`/llms.txt`** — a compact, factual brief of the business: NAP, credentials, founding date,
  ownership, ratings, every service with a one-paragraph definition, every service area, and
  the full FAQ set, with explicit citation guidance.
- **`robots.txt` explicitly allows** GPTBot, OAI-SearchBot, ChatGPT-User, PerplexityBot,
  ClaudeBot, Claude-SearchBot, Google-Extended, Applebot-Extended, Amazonbot, meta-externalagent
  and cohere-ai. Most contractor sites accidentally block these.
- **Entity consistency** — name, address and phone are emitted from one source of truth, so the
  NAP string is byte-identical across all 25 pages, `llms.txt` and every schema block.
- Outbound citations to authoritative third parties (Real Log Homes, Angi, HomeAdvisor, BBB,
  Houzz) so claims are corroborated off-site.
- Concrete, checkable assertions — dates, counts, ranges, county names — instead of adjectives.

## Accessibility & performance

- WCAG 2.2 AA colour contrast throughout (verified numerically, not by eye).
- Skip link, visible focus rings, labelled form controls, keyboard-operable gallery lightbox,
  `aria-current`, `aria-expanded`, landmark regions.
- Full `prefers-reduced-motion` support — every animation, count-up and scroll reveal degrades
  to its final state.
- No JavaScript framework. Total JS ≈ 7 KB. Total CSS ≈ 45 KB. No web-font FOIT.
- All artwork is inline SVG: nothing to download, nothing to lazy-load, no layout shift.


## Editing content

Everything the client will ever want changed lives in **`src/data.py`**: phone, address, hours,
services, service areas, FAQs, testimonials, ratings, project types. Change a value once,
run `python3 build.py`, and it updates across every page, the sitemap, `llms.txt` and all
schema blocks at once.

### Using the original logo artwork

The header and footer lockups are currently **redrawn as SVG** from the client's logo — sharp at
any size, theme-aware, and weightless. To use the original artwork instead, drop the file in as
`src/assets/img/logo.png` (or `.svg`/`.webp`) and rebuild. The build detects it and swaps it in
everywhere automatically. `logo-stacked.*` overrides the footer lockup separately.

## Deploying

The `site/` folder is a plain static site — deploy it anywhere.

| Host | How |
| --- | --- |
| **Netlify** | Drag `site/` onto the deploy page, or connect the repo with build `python3 build.py` and publish directory `site`. `_headers` is picked up automatically. |
| **Vercel** | Output directory `site`. |
| **Cloudflare Pages** | Build `python3 build.py`, output `site`. |
| **Any host** | Upload the contents of `site/` to the web root. |

Point `www.krainconstructionllc.com` at the host and enable HTTPS.

## Going live

Three values in `src/data.py` turn the site from demo to production:

```python
FORM_ENDPOINT = ""   # Formspree / Netlify Forms / CRM webhook URL
GA4_ID        = ""   # "G-XXXXXXXXXX"
GOOGLE_ADS_ID = ""   # "AW-XXXXXXXXX"  (+ GOOGLE_ADS_CONVERSION_LABEL)
```

With `FORM_ENDPOINT` empty the form runs in **demo mode**: it validates fully and routes to
`/thank-you/`, but sends nothing. Set the endpoint and submissions POST for real — the
thank-you redirect and conversion tracking are already wired.
