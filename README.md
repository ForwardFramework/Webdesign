# Booth's Contracting — website

Marketing site for **Booth's Contracting**, a concrete, excavation and landscaping
contractor in Western Pennsylvania. Built as a static site: 28 pages generated by a
zero-dependency Node script, deployed to Netlify, with lead capture through Netlify Forms.

- **Live build:** `node build.mjs` → `dist/`
- **Stack:** plain HTML/CSS/JS. No framework, no npm dependencies, no client-side routing.
- **Performance:** self-hosted fonts, no third-party requests, ~35 KB of CSS and ~7 KB of JS.

## Before you launch — read this first

Ten things were inferred from the flyer and logo rather than confirmed. Fix them in
`data/site.mjs` (every one is flagged `// VERIFY`) before the site goes public.

| # | Item | Where | Why it matters |
|---|------|-------|----------------|
| 1 | **Domain** | `site.url` | Canonical tags, sitemap URLs, Open Graph images and JSON-LD all read from it. Wrong domain = wrong canonicals across 28 pages. |
| 2 | **Home city and service radius** | `site.city`, `site.geo`, `site.serviceRadiusMiles` | Butler, PA was inferred from the 724 area code. If the real base is elsewhere, the ten town pages and all local schema are pointed at the wrong place. |
| 3 | **Email address** | `site.email`, `site.leadEmail` | `info@boothscontracting.com` is a guess. |
| 4 | **Social URLs** | `site.social` | `@boothscontracting` came from the flyer; confirm the exact profile URLs. |
| 5 | **PA HIC licence number** | `site.trust.licenseNumber` | Currently a placeholder, so it is deliberately **omitted** from structured data. Fill it in and it publishes. |
| 6 | **"Licensed & insured" / "Free estimates"** | `site.trust` | Stated as fact on every page. Confirm both are true. |
| 7 | **Business hours** | `site.hours` | Published in the footer, on the contact page, and in `openingHoursSpecification`. |
| 8 | **Legal entity name** | `site.legalName` | Used in the copyright line and `legalName` schema. |
| 9 | **Price ranges** | `data/services.mjs`, `services` page | Realistic Western PA market ranges, but they are ours, not Booth's. Adjust to actual pricing. |
| 10 | **Service area town list** | `data/areas.mjs` | Ten towns have their own landing page. Swap any that are outside the real radius. |

Two more things ship intentionally empty, because inventing them would be both
dishonest and a Google penalty risk:

- **`data/testimonials.mjs`** — no reviews. The home page shows a "see the work on
  Facebook" panel instead. Paste in real reviews and the section switches on.
- **`data/gallery.mjs`** — no project photos. The gallery page points at Facebook and
  Instagram, and the home page drops its gallery section entirely. Add photos and both
  appear. **Adding real photos is the single highest-value thing you can do for
  conversions on this site.**

## Deploying to Netlify

### Option A — connect the Git repo (recommended)

1. In Netlify: **Add new site → Import an existing project → GitHub**, pick this repo.
2. Netlify reads `netlify.toml` and fills in the build settings itself:
   - Build command: `node build.mjs`
   - Publish directory: `dist`
3. Deploy. Every push to the branch rebuilds the site.

### Option B — deploy from this machine

```bash
npm install -g netlify-cli
netlify login
node build.mjs
netlify deploy --dir=dist --prod
```

### Immediately after the first deploy

1. **Turn on form notifications.** Site configuration → Forms → Form notifications →
   add an email notification for both `quote-fast` and `quote-detailed`. Without this,
   leads land in the Netlify dashboard and nobody gets an email. *Do this first.*
2. **Add spam protection.** Forms → Settings → enable reCAPTCHA or keep the built-in
   honeypot (already wired as `bot-field`).
3. **Attach the domain.** Domain management → add the custom domain, then set
   `site.url` in `data/site.mjs` to match and redeploy.
4. **Submit the sitemap** at `https://yourdomain.com/sitemap.xml` in
   [Google Search Console](https://search.google.com/search-console) and Bing Webmaster Tools.
5. **Claim the Google Business Profile.** For a local contractor this outranks
   everything on this list combined — the site supports it, it does not replace it.

## Editing the site

Everything is driven by four data files. You rarely need to touch the templates.

| File | Controls |
|------|----------|
| `data/site.mjs` | Name, phone, email, hours, service area, promo bar, analytics ID |
| `data/services.mjs` | The seven service pages — copy, bullets, process, FAQs, pricing |
| `data/areas.mjs` | The ten town pages, plus the wider list of towns served |
| `data/testimonials.mjs` | Customer reviews (empty until there are real ones) |
| `data/gallery.mjs` | Project photos (empty until there are real ones) |

Common edits:

```bash
# Change the phone number everywhere (site, schema, call bar, llms.txt)
$EDITOR data/site.mjs      # phone, phoneHref, phoneDisplay

# Turn off the seasonal announcement bar
$EDITOR data/site.mjs      # promo.show = false

# Add a service — it appears in the nav, the grid, the quote dropdown,
# the sitemap and the structured data automatically
$EDITOR data/services.mjs

# Switch on Google Analytics
$EDITOR data/site.mjs      # ga4Id = 'G-XXXXXXXXXX'
```

### Using the real logo artwork

The header logo is currently rendered in CSS from the brand fonts, which is sharp at
every size and costs no network request. To use the actual logo file instead, drop it
into `public/assets/img/` and set one line:

```js
// data/site.mjs
logoImage: '/assets/img/logo-artwork.png',
```

A transparent PNG about 800px wide works well. The rendered wordmark in
`public/assets/img/logo.png` (used in structured data) can be replaced the same way.

### Adding project photos

```bash
# 1. Resize to ~1600px wide, save as JPEG at ~75% quality
# 2. Drop them in:
cp ~/photos/driveway-cranberry.jpg public/assets/img/gallery/
# 3. Add an entry per photo in data/gallery.mjs — the `alt` text is what
#    Google Images ranks on, so describe the actual work
```

## Local development

```bash
node build.mjs          # build to dist/
npm run dev             # build and serve at http://127.0.0.1:8099
npm run audit           # crawl every built page for SEO/a11y problems
npm test                # drive the forms and navigation in a real browser
```

`npm run audit` and `npm test` need a server running on port 8099 (`npm run preview`)
and Playwright available. Neither is needed to build or deploy — they are pre-flight
checks, not part of the build.

The audit fails the run on: console errors, duplicate IDs, broken internal links,
missing `alt` text, skipped heading levels, unlabelled form fields, missing or
over-length titles and descriptions, missing canonicals, and malformed JSON-LD.

## How the SEO / AEO / GEO work is set up

**Classic SEO**

- One `<h1>` per page, no skipped heading levels, descriptive internal links
- Unique title (≤ 62 chars) and meta description (≤ 165) on every page, enforced by the audit
- Canonical URL on every page; `thank-you`, `privacy`, `terms` and `404` are `noindex`
- `sitemap.xml` generated from the page manifest, with per-page priority and change frequency
- Ten town pages with genuinely different copy — near-identical town pages get filtered
  out of local results as doorway pages, so each one describes real local conditions
- Clean URL structure (`/services/<slug>/`, `/service-areas/<slug>/`) with short vanity
  redirects (`/quote`, `/driveways`, `/patios`) for print and vehicle lettering

**Answer engines (AEO)**

- Every service and town page opens with an **answer box**: a single self-contained
  paragraph that answers the page's question in a form an assistant can quote directly
- `FAQPage` structured data on the home, FAQ, service and town pages — 46 questions in
  all, each with a direct, specific answer rather than a lead-in to a sales call
- Honest, checkable numbers throughout (PSI, base depth, frost depth, cure times, prices)
  because answer engines reward specificity and punish vagueness

**Generative engines (GEO)**

- `/llms.txt` — a plain-language summary of the business, services, service area and
  typical pricing, written for AI assistants to read
- `robots.txt` explicitly allows GPTBot, ClaudeBot, PerplexityBot, Google-Extended and
  the rest. Being quotable is the whole point for a local contractor
- Geo meta tags (`geo.region`, `geo.position`, `ICBM`) plus a `GeoCircle` service area

**Structured data** (one `@graph` per page, all cross-referenced by `@id`)

`GeneralContractor` + `LocalBusiness` · `WebSite` · `WebPage` / `CollectionPage` /
`ContactPage` · `BreadcrumbList` · `Service` · `OfferCatalog` · `FAQPage` · `ItemList`

**Deliberately absent:** `Review` and `aggregateRating`. Marking up reviews that were
never left is a manual-action risk, and Google filters self-serving review markup anyway.
Once there are three or more real reviews in `data/testimonials.mjs`, add the markup in
`src/templates/schema.mjs` — there is a note in that file.

## How the lead capture works

Two Netlify forms, each posting to `/thank-you/`:

| Form | Where | Fields |
|------|-------|--------|
| `quote-fast` | Home hero, every service page, every town page, about page | Name, phone, ZIP, service |
| `quote-detailed` | Contact page | Name, phone, email, address, service, timeline, budget, details, contact preference |

The short form is deliberately four fields — each extra field costs conversions, and
name plus phone is everything needed to call somebody back.

Both forms:

- **Work with JavaScript disabled.** JS adds inline validation and phone formatting;
  it is not required to submit.
- **Stamp lead attribution.** The first campaign that brought the visitor in (`utm_*`,
  `gclid`, `fbclid`, referrer, landing page) is kept for 30 days and attached to the
  submission, so you can tell which ad or post produced the job. It arrives in the
  `attribution` field of every lead.
- **Record the source page** in `submitted_from`, so you know a lead came from the
  Cranberry patio page rather than the home page.
- **Prefill the service** when submitted from a service page.
- **Carry a honeypot** (`bot-field`) that Netlify uses to drop bot submissions.

Conversion events (`generate_lead`, `click_to_call`, `click_to_text`) are pushed to
`gtag` and `dataLayer` when either is present, so they hook into GA4 or GTM with no
code changes — just set `ga4Id` or `gtmId` in `data/site.mjs`.

```
netlify.toml            Build settings, redirects, security and cache headers

  services.mjs          Seven service pages

  gallery.mjs           Project photos (empty)
src/
  templates/
    layout.mjs          HTML shell — head, meta, Open Graph, icons
    ui.mjs              Header, footer, forms, cards, CTA bands, FAQ, gallery
    schema.mjs          JSON-LD graph builders
    icons.mjs           Inline SVG icons
  pages/
    home.mjs  services.mjs  areas.mjs  static.mjs
public/                 Copied verbatim into dist/
  assets/css/site.css   Design system and all page styles
  assets/js/site.js     Progressive enhancement only
  assets/fonts/         Self-hosted Inter, Oswald, Kaushan Script (latin, ~105 KB)

scripts/
  render-assets.mjs     Regenerates logo, social card and app icons from HTML
  audit.mjs             Pre-deploy SEO and accessibility crawl
  functional-test.mjs   Browser tests for forms and navigation
  shots.mjs             Screenshots for visual review
docs/design-tooling.md  Notes on the design skills and MCP server in this repo
```

## Brand

Taken from the logo and the seasonal flyer.

| Token | Value | Use |
|-------|-------|-----|
| `--ink` | `#0E2029` | Logo badge, dark sections, body text base |
| `--gold` | `#F6C445` | Logo lettering, primary buttons, accents |
| `--gold-800` | `#8A6206` | Gold **text** on light backgrounds (passes 4.5:1) |
| `--concrete` | `#EDEBE6` | Alternating section backgrounds |
| `--rust` | `#C9622A` | Seasonal accent, carried from the flyer |

Type: **Oswald** for headings and UI (the flyer's condensed industrial caps),
**Inter** for body, **Kaushan Script** for the "Booth's" wordmark and script accents.

All colour pairs used for text meet WCAG AA (4.5:1). Gold on a light background is the
one trap in this palette — use `--gold-800` for text and keep `--gold` for fills.
